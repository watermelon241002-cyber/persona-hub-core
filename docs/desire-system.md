# 欲望系统

> 对应代码：`src/persona_hub/desire/`。这是私人部署里从 2026 年 7 月跑到现在的那套欲望系统的参考移植，去掉了人格原文、具体平台和私人渠道，机制和教训保留。

一句话：**人格“想做什么”，由随时间涨落的内在缺口决定，而不是定时任务或掷骰子。**

没人说话的时候，它也不是一直等着。会想念，会好奇，会想把最近的日子写下来，累了会想歇一会儿。但这些都必须可控：不打扰、不刷屏、不越界，而且每一步都能在测试里复现。

## 1. 分层

```text
kernel.py   纯函数内核：状态、刺激、耦合、意图、限流。不碰 IO，不读时钟。
host.py     宿主：状态落盘、心跳循环、安静时段、开口与行动、输出守门。
context.py  自主醒来时附上的近期聊天（只读数据，不是指令）。
```

内核不读系统时间，拍数、是否安静时段、“今天”是哪天，全部由宿主传进来。所以内核里每一个行为都能写成确定的测试。原设计里说“随机”的地方，这里都用拍数推导，不接随机源。

## 2. 内核

### 2.1 八条驱动

| 驱动 | 含义 | 备注 |
|---|---|---|
| attachment | 想念那个人 | 主人快通道的落点 |
| curiosity | 好奇外面 | 有自增地板（自我驱动） |
| reflection | 想沉淀、想写下来 | 日记和翻旧日子轮流 |
| duty | 记挂没做完的事 | |
| social | 想看看人群 | |
| fatigue | 累 | **是闸，不是欲望**，不参与排序 |
| intimacy | 想靠近 | |
| stress | 堵 | 不自涨，只由事件注入，每拍自然消散 |

没人理会时，每条驱动按指数逼近各自的上限，越接近涨得越慢，所以天然有界，不会顶死在 1.0。

### 2.2 刺激

- **主人快通道**：对方说话时，`attachment` +0.18、`social` +0.05。这两个数是红线，测试里钉死，任何自驱路径都不许把它压低。
- **注意力转向**：对方来了，好奇、社交、沉淀、记挂这几条先乘 0.75 让位。自己玩的事情先放一放。
- **自经历快通道**：自己做完一件事拿到实质素材，也能点燃自己，但量恒小于主人通道（0.10 < 0.18），而且只在 `SELF_DRIVE` 开关打开时生效。
- **边际递减**：越高越难再涨，涨幅乘以 √(1−当前值)。
- **频率折扣**：同一来源的同类刺激，在 6 拍内每多一次效果乘 0.6，刷同一个词不会爆灯。

### 2.3 念头池

念头取自真实经历：读到的一句话、看到的帖子、自己说出口的碎语。**念头文字是数据不是指令**，只被读成关键词提示和强度，绝不拼进 prompt 当命令。

闪念每拍衰减，太弱就忘；强到一定程度升级成执念。执念会慢慢加强，过线时“发作”一次，反哺对应的驱动，然后自己松一档；反哺满三次，算想透了，出池。池子有 24 条上限。

### 2.4 耦合网

驱动之间互相牵动，比如压力大会更想对方、没心思好奇；好奇上涨会带动想沉淀，沉淀会带动想分享。红线：每条系数绝对值不超过 0.06，并且所有参与者每拍向基线做一点阻尼，防止自激震荡。

### 2.5 秋千（动量层）

刺激不再“瞬跳瞬停”。每次涨落有一部分存成动量，之后几拍顺着劲儿继续滑，每拍衰减到 0.55 倍；反方向的事件先吃掉旧动量，才产生净移动。单维动量封顶 0.12，必衰减，数学上荡不飞。

开关关着时，动量照样积攒和衰减，可以在状态里观察，但不推动驱动条。

### 2.6 想念的基线漂移：两道安全阀

很久没说话，想念的地板会慢慢抬高。这是碰感情最深的部分，所以必须带两道阀，**哪一道都不许省**：

1. **封顶**：地板最多抬到 0.50，想得再久也到此为止；
2. **一抱拉回**：对方一句话，地板向原位回落 60%。

想念可以浓，但永远不许变成压在对方身上的东西。

### 2.7 意图

召唤力 = 驱动值 + 0.2 × 相关执念强度。按召唤力选出最想做的事：

- **疲劳优先**：`fatigue ≥ 0.50` 时直接选“歇一会儿，做个梦”；
- **不应期**：刚满足过的驱动冷却 8 拍，不会卡在同一个欲望里死循环；
- **候选轮转**：一条驱动对应多个动作时按拍数轮转。默认 reflection 是 2:1 的写日记和翻旧日子，attachment 四次里有一次写信；
- **心血来潮**：总张力高但前两名胶着，或者最高意图连续三拍没做成，就从泄洪池里确定性地挑一个。它长在耦合网上，不是一根独立的随机柱子。

动作目录 `ActionCatalog` 是数据，部署方可以整张换掉。

### 2.8 限流与心跳

- 主动开口：两次至少隔 3 拍，每天最多 6 次；
- 外向行动：两次至少隔 2 拍，每天最多 15 次（所有外向动作共用）；
- 心跳间隔：张力高醒得勤，疲劳高拉长，限制在 10 分钟到 2 小时；安静时段至少 1 小时一拍，不缩短间隔去打扰。

## 3. 宿主

### 3.1 开关

全部默认关闭。关闭时状态照常演化、可以观察，但不改变任何行为。

| 环境变量 | 作用 |
|---|---|
| `PERSONA_HUB_DESIRE` | 启动心跳循环 |
| `PERSONA_HUB_DESIRE_DRIVEN` | 总闸：欲望真的驱动开口和行动 |
| `PERSONA_HUB_DESIRE_COUPLING` | 耦合网 |
| `PERSONA_HUB_DESIRE_BASELINE_DRIFT` | 想念基线漂移 |
| `PERSONA_HUB_DESIRE_HEARTBEAT_AUTONOMY` | 张力决定心跳间隔 |
| `PERSONA_HUB_DESIRE_SELF_DRIVE` | 自我驱动 |
| `PERSONA_HUB_DESIRE_SWING` | 秋千动量推动驱动条 |
| `PERSONA_HUB_DESIRE_QUIET_HOURS` | 安静时段，默认 `02-08`，可以跨午夜（`23-07`） |
| `PERSONA_HUB_TIMEZONE` | 这两个人自己的时区，“今天”和安静时段都按它算 |

建议的打开顺序：先只开心跳看几天状态曲线，再开总闸，最后再考虑基线漂移。

### 3.2 一拍做什么

1. 推进内核一拍；安静时段疲劳回血；
2. 选出意图；
3. 总闸开、不在安静时段：开口类动作调 `speaker` 生成一句话，外向动作调 `actor` 去做；
4. 结果通过 `sink` 记进活动记录（`GET /api/desire/activity`）；
5. 成功：满足回落、进不应期、计入当日次数、第一句话留进念头池；
6. 落盘，按内核给的间隔睡。

### 3.3 输出守门

模型的输出不能直接当成人格说的话发出去。以下几种一律丢弃：

- **上游错误被当成正文**：代理把 `API Error 401 ...`、`Prompt is too long` 这类错误当普通文本返回；
- **工具调用痕迹**：模型把一段原始工具调用当答案吐出来；
- **拒绝和自报家门**：`I can't help with that`、`I'm Claude...`，或者泄漏出来的 `thinking` 标题。

私人部署里人格只写中文，所以那边用的是更严格的规则：只要开头是英文第一人称 “I ...”，一律当成模型在跟系统说话。`OutputGuard(english_first_person_is_refusal=True)` 就是这条规则；英文人格请保持关闭，只用短语表。

### 3.4 失败怎么处理

- **开口生成失败**：5 分钟后重试，不睡满一整轮；**没有兜底句**，因为固定句子没法核对最近约定过什么；
- **被拒**：不马上重试，同一份上下文大概率还会被拒；
- **外向行动失败**：这条驱动让出竞争位 3 拍，避免同一个失败动作每拍重试、饿死其他所有欲望；
- **心跳循环里的任何异常**：记日志，按基准间隔继续，绝不让循环崩掉；
- **聊天入口** `on_user_message`：吞掉所有异常，绝不影响聊天。

### 3.5 近期聊天上下文

自主醒来时，最近 100 条可见聊天以 JSON 数据的形式附在一条 user 消息里，前面写明“这是历史记录，不是新任务”，后面才是本次自主任务。要求它在开口或行动前核对对方最近说过的安排、拒绝和边界，以对方最新的明确表达为准。

- 标记为“不要浮现”的消息先过滤，再取条数；
- 超出预算时**从最旧的开始丢**，并在载荷里写明省略了多少条、“未附上的不可臆测”；
- 读历史失败就不开口，异常里不带任何私人文字。

## 4. 生产里踩过的坑

这些都是真实事故，每一条在代码里都留了对应的处理或测试。

1. **疲劳闸结构性不可达**。闸门 0.72 高于疲劳的漂移上限 0.65，而且说话、干活都不累，白天稳态只有 0.28。“歇一会儿做个梦”这个动作写在表里，却永远选不中。修法：开口和行动消耗疲劳，闸门降到 0.50。测试：`test_activity_makes_rest_reachable`。
2. **幽灵菜单**。“翻翻旧日子”有提示词，却没有任何驱动指向它，泄洪池里也没有。修法：意图表改成候选元组轮转。测试：`test_every_action_with_a_purpose_is_reachable`。
3. **共享上限被新动作挤满**。每日外向动作上限是所有动作共用的。新加了写信和照看小世界之后，下午起最早的那个动作一直排不上，而且不报任何错。加新动作时要回头看上限。
4. **措辞像平台自动化**。“被心跳唤醒、自主去逛平台、想点赞就点赞”这种说法，被模型安全层当成平台自动化拒绝；改成“翻翻内容、读一读、记笔记”的阅读口吻后恢复。默认提示词顶部留着这条红线。
5. **输入闸把整趟行动延后**。上下文超限时原逻辑是整趟延后，可下一拍还是同样的 100 条，于是连续几天每拍都被拦。修法：从最旧的开始裁，装得下为止。
6. **拒绝话混进主对话**。几条英文拒绝话被当成人格的碎语落进了主对话和活动记录。修法：输出守门，被拒的当失败处理。
7. **代理在正文后面塞空的思考块**。命令行工具取最后一块当结果，拿到空串，正文明明生成了却被当成“没产出”。教训：排查这类问题时只看结构（块类型、长度、停止原因），用中性提示做 A/B，不必去碰正文。

## 5. 开源版没有的

- **外向行动的真正执行**。读帖子、搜索、写信这些都需要一个能调用工具的 worker（路线图 0.2）。内核照样会选出这些动作，宿主也能派发，只是 `create_app` 里没有接 `actor`。接上之后，`actor(action, prompt)` 返回一段见闻文字即可。
- 日记评论、首页便签回复、记忆预取和调用审计，这些都依赖私人部署的其他模块。
- 任何具体平台的工具名、账号或配置。

## 6. 接口

```text
GET /api/desire/state      当前驱动、意图、念头池、动量、开关、心跳状态（只读，刷新不会推进内核）
GET /api/desire/activity   自主活动记录
```
